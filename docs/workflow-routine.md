# Work Routine

## Purpose

This project uses a consistent execution routine so implementation work stays aligned with product intent and progress remains visible.

## Default Routine

1. Think broadly before starting the next task.
2. Decide the next step based on product impact, architecture fit, and current repo state.
3. Track progress through the active work todo flow.
4. When a work todo is completed, record the completed work in a markdown file under `docs/`.
5. After the documentation update, review git state, commit the finished work, and push it to the remote branch.

## Progress Update Minimum

Each markdown progress update should include:

- completed todo or milestone name
- summary of what changed
- files or systems affected
- validation performed
- remaining issues, blockers, or next steps

## Git Routine

- commit only completed, coherent work
- use a clear message focused on why the milestone was completed
- push after the markdown progress update is written
- if the repo state is unsafe for push, stop and explain the issue before proceeding

## Notes

- This routine is meant to support iterative MVP delivery.
- The routine favors small milestone pushes over large delayed batches.
